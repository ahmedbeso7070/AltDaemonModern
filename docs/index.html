THE DETAILS

The familiar workflow
A repaired foundation.

Native authentication, compatibility work and bounded recovery in one independently maintained daemon.

01

Native first.

Try on-device AuthKit anisette before the v3 path. Keep stable provisioning state and remember a successful fallback provider.

A custom provider can replace the public fallback sequence.

02

Keep the protocol.

Preserve AltStore’s XPC workflow, with compatibility updates for Apple authentication identity and transient service failures.

Current source includes iOS 26 InstallCoordination support.

03

Recover with care.

Serialized requests, bounded retries, redacted diagnostics, and staged AltStore self-refresh that lets App Intents finish first.

Device and jailbreak compatibility are separate from API support.

GETTING STARTED

Your existing AltStore
Refreshed on device.

Start with a compatible AltStore Classic installation and standard rootless environment.

Full installation guide ↗
  1. Prepare AltStore Classic.

    Use a compatible Classic build and supported jailbreak. Device-specific installation routes are in the repository guide.

  2. Add ichitaso’s repository.

    Add https://cydia.ichitaso.com/ in Sileo or a compatible package manager, then install AltDaemon Modern. The GitHub DEB is an alternative.

  3. Reopen AltStore.

    Fully close and reopen it, then use Refresh All.

  4. Automate if useful.

    Optionally create a daily Shortcuts automation with Refresh All Apps.

For the 1.2.2 update, install over the existing package. Do not routinely sign out or reset anisette state. Follow the current repository guide for device-specific AltStore setup.

A LITTLE MORE CONTEXT

Good to know.

Does it need an anisette server every time?+

It tries native AuthKit first. Anisette v3 is the fallback; a custom configuration can select or replace that path.

Does AltDaemon receive my Apple ID password?+

No. Apple-account authentication stays between AltStore/AltSign and Apple. The v3 provider handles a provisioning identifier and ADI data, which has its own trust considerations.

Can I use RootHide?+

RootHide is outside this package’s supported standard /var/jb environment. Do not assume another rootless layout is interchangeable.
